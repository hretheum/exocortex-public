# F1.11. Publication classes and path classification

[← F1](../F1-public-repo.md)

## Why

The publisher treats every file the same way, so project documentation gets the same tests as experiment data. Before we change the tests, every path needs a class.

## What to do

1. Add the module `tools/publisher/classes.py` with the class list and paths from the table in the [design document](../../05-publication-design.md): project documentation, experiment, generated page, unknown.
2. Classify by relative path, without reading the file header. A path outside the list, a file with an extension other than `.md` and `.svg` in the documentation class, and a file over the size limit go to the unknown class.
3. Print the class of every file in a dry run and in the run log, and report a file of the unknown class in the notification.
4. Write tests for every rule, including the paths `experiments/`, `data/`, `generated/` and the registry, which are never documentation.

## Done when

A dry run on the current vault prints the class of every file, no file from `experiments/` or `data/` is documentation, and the tests pass in CI.

## Progress
