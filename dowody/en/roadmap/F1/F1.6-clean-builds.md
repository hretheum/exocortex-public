# F1.6. Image and package from the clean repository

[← F1](../F1-public-repo.md)

## Why

The container image and the Python package are evidence too: they let anyone run the engine without building it themselves. They go back to the public registries, but only from the clean repository and only through the scanner.

## What to do

1. Turn `.dockerignore` into an allowlist: the first line excludes everything, the following lines admit specific folders.
2. In the Dockerfile, replace `COPY . .` with explicitly named folders.
3. Workflow: build, `leakgate scan-image`, push to GHCR. For the package: build the wheel and sdist, run `leakgate scan-wheel` and `scan-sdist`, publish to PyPI through trusted publishing, with no token in secrets.
4. A new package version (0.2.0) with the new repository address in its metadata.
5. Make the GHCR packages built from the new repository public. The old packages stay private or are deleted (decision in F0.1).

## Done when

An anonymous `podman pull` fetches the new image, and the list of files in it matches the allowlist. Package 0.2.0 installs and its contents pass the scanner. The workflow has no publishing path that skips the scanner.
