# F1.9. Publisher on K12

[← F1](../F1-public-repo.md)

## Why

The repository should show the current state without anyone publishing by hand. The publisher is the only way from the vault to the repository, so all the checks are built into it.

## What to do

1. The `_source/dowody` folder reaches K12 through Syncthing. The publisher mounts it in its container read-only.
2. On K12, a rootless Podman pod started by Quadlet, with a timer every 15 minutes. No source code goes to the server: the publisher runs from a container image and keeps only a partial clone with the `dowody/` folder. A run:
   - checks the lock flag from F0.7 and stops if it is set,
   - copies changed files into a working copy of the repository,
   - runs the scanner, the private corpus comparison, the parity check and the language check,
   - commits the files that passed in one commit with an English message and pushes,
   - leaves held files in place and records the reason in the run log.
3. Notification about a held file: to Telegram if the bot is configured, otherwise by email.
4. The publisher has its own account or a deploy key with write access to this repository only.

## Done when

A change to a file in the vault shows up in the repository within 30 minutes. A file with a canary is held and the notification arrives. Nothing is published while the lock flag is set.
