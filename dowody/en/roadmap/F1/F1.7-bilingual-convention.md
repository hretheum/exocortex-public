# F1.7. Bilingual convention and parity check

[← F1](../F1-public-repo.md)

## Why

The rule "every document in Polish and in English in the same commit" has to be checked automatically. Otherwise the versions start to drift: a fix lands in one, a number changes in the other.

## Convention

- Two parallel trees, `dowody/pl/` and `dowody/en/`, with identical file names. File names are in English.
- In the header of every file: `lang` and `counterpart` with the path to its pair.
- Links only as plain markdown links with relative paths, no Obsidian wiki links. Such links work both in Obsidian and on GitHub.
- A glossary, `dowody/glossary.yaml`: Polish term, English term, short definition. For example bramka and gate, karta hipotezy and hypothesis card, zbiór kontrolny and control set.

## What to do

1. Describe the convention in the repository README, in both languages.
2. Write `paritycheck` (code in English), which checks each pair: do both versions exist; do they have the same number and levels of headings; the same set of numbers; the same links after normalisation; tables of the same shape; the same `id`, `status` and `depends_on` values in the header.
3. Add the check to CI and to the publisher. A file without a pair, or with a mismatch, is not published.
4. A helper mode: for a file without a pair, generate a draft translation with a local model and the glossary, marked `translation: machine` in the header, for a person to review before publication.

## Done when

`paritycheck` passes on the current `dowody/` folder and fails in three prepared cases: a missing pair, a different number in one version, a missing heading.
