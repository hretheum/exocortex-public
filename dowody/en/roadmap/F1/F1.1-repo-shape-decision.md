# F1.1. How the public repository is created

[← F1](../F1-public-repo.md)

## Why

The history of the current repository contains material that cannot be public. We have to choose how to arrive at a repository that is safe to open, and where it should live.

## Options

A. A new repository with a clean history at the existing address `hretheum/exocortex`. The current repository is renamed to `exocortex-private` and stays private. The code moves to the new one through an export (F1.3). Advantage: the address the project website and the package metadata point to works again, and the history contains nothing from old commits. Drawback: the public history starts on the day of the export.

B. Rewrite the history of the current repository (`git filter-repo`) and open it. Advantage: history is kept. Drawback: a single missed file in any of several hundred commits is enough, and any copy made before the rewrite still contains everything.

C. Two repositories, one for the engine and one for the lab. Advantage: a cleaner split. Drawback: a reviewer has to look in two places, and the evidence cycle touches both.

## Recommendation

Option A, one repository with folders for the engine, the lab and the documents (`dowody/`). The missing old history can be explained honestly in the README: the public history starts with the export, and earlier work was done in a private repository.
