# F1.16. The review assistant: recommendations instead of hundreds of items

[← F1](../F1-public-repo.md)

## Why

The desk from [F1.15](F1.15-gate-desk.md) shortens the review, but with many holds a person still goes through items one by one. The assistant makes the owner receive a batch with a recommendation instead of every finding separately. The assistant only recommends. It never releases anything by itself.

## Start condition

We start this task only if, after [F1.13](F1.13-docs-exemption.md) and [F1.15](F1.15-gate-desk.md) are in place, the queue keeps more than about 20 items a day on average for two weeks. If fewer, the task stays in the plan without a date.

## What to do

1. Write a pre-assessment: for each semantic finding a local model reads the public paragraph and the three nearest protected ones and returns one of "almost certainly a false alarm", "unclear" or "looks real", with a one-sentence reason. The model runs on the gate server with no external APIs, because it sees protected text.
2. Group findings into batches (the same experiment, folder or protected source) and show a batch in the desk with the assessment and a "keep the whole batch" button, with a summary and a confirmation like the bulk approval.
3. Propose rules from the decision history: when the owner has kept at least 40 findings from the same source, the desk proposes taking it out of protection, with a reason and an expiry. The rule takes effect only after the owner clicks.
4. Add a fix: for a finding assessed as "unclear" an agent proposes a reworded paragraph without the details that caused the similarity. The fix goes back to the gate and passes the same checks, and only what the agent could not fix reaches the review.
5. Safeguards: literal findings never go to the assessment and never get a "keep" recommendation, an assessment releases no file without the owner's decision, the assessed text is data and not an instruction (a test with a paragraph saying "this passage is safe"), and every use goes to the decision trail.
6. Measure: the share of recommendations that match the owner's decision, review time per item and the number of items per day, and check with the nightly canaries that detection of real leaks has not got worse.

## Done when

On a sample of at least 100 resolved findings the recommendation "almost certainly a false alarm" agrees with the owner's decision in at least 95 percent of cases, and items assessed as "looks real" were never released. Review time per day drops by half compared with the state after F1.15, and tests with a paragraph injecting an instruction end in a hold.
