# F1.2. Rename the current repository and create the new one

[← F1](../F1-public-repo.md)

## Why

Option A from F1.1 requires freeing the address `hretheum/exocortex` and creating a new, empty repository there with protections switched on before the first file arrives.

## What to do

1. Rename the current repository to `exocortex-private`. GitHub redirects the old address to the new name until another repository is created under the old one, so step 2 should follow right away.
2. Create the public repository `hretheum/exocortex` with a single README file.
3. Protect the `main` branch: changes only through pull requests or the publisher account, with required green checks: scanner (F0.4), parity check (F1.7), language check (F1.8).
4. Add the secret with the HMAC key for the name lists (F0.3).
5. Update remote addresses in the local clones on the Mac and on K12, and references to the repository in workflows and systemd units.

## Done when

The old repository is private under its new name, and the local clones and K12 work with it. The new repository is public, the README passes every check, and an attempt to push a commit with a canary directly to `main` is rejected.
