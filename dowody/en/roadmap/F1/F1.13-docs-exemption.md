# F1.13. Exempting project documentation from security testing

[← F1](../F1-public-repo.md)

## Why

Almost all documentation holds are semantic and come from a shared topic, not from a leak. Documentation should go out without the semantic comparison, but not without the literal scanner.

## What to do

1. Assign sets of checks to the classes: documentation gets the literal scanner at the blocking level, parity, schemas and language, while an experiment and a generated page get everything.
2. Take the documentation class off the review page and out of paragraph approvals.
3. Extend the nightly self-test with canaries in every class, documentation included, so that a miss sets the lock as it does today.
4. Record the size limit of a documentation file in the configuration, and describe in the gate README how to switch off every test for a class (one line), together with the risk.
5. Ask the owner for the scope of the exception (decision 1 in the design document) and record the answer.

## Done when

The documentation files held today by the semantic comparison go out within 30 minutes, a canary in documentation is held, and a self-test with a missed canary sets the lock.
