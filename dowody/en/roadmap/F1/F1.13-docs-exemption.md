# F1.13. Exempting project documentation from security testing

[← F1](../F1-public-repo.md)

## Why

Almost all documentation holds are semantic and come from a shared topic, not from a leak. Documentation should go out without the semantic comparison, but not without the literal scanner.

## What to do

1. Assign sets of checks to the classes: documentation gets the literal scanner at the blocking level, parity, schemas and language, while an experiment and a generated page get everything.
2. Take the documentation class off the review page and out of paragraph approvals.
3. Extend the nightly self-test with canaries in every class, documentation included, so that a miss sets the lock as it does today.
4. Record the size limit of a documentation file in the configuration, and describe in the gate README how to switch off every test for a class (one line), together with the risk.
5. Ask the owner for the scope of the exception (decision 1 in the design document) and record the answer.

## Done when

The documentation files held today by the semantic comparison go out within 30 minutes, a canary in documentation is held, and a self-test with a missed canary sets the lock.

## Progress

- 2026-09-29: every class has a set of checks (`CHECKS` in `tools/publisher/classes.py`). Documentation skips the semantic comparison, does not appear on the review page and needs no paragraph approvals. It keeps the literal scanner at the blocking level, the machine translation rule, parity, schemas and the language check. Scanner warnings do not hold a documentation file; they go to the run log (the `warnings` field). An experiment, a generated page and the unknown class get every check. The nightly self-test plants canaries in seven paths of the four classes and checks them with the publisher's checks. In CI it caught 101 of 101 cases. The tests show that a canary with synthetic personal data in documentation is held, and that skipping the scanner for documentation or a scanner miss sets the lock. Switching off every check for documentation is one line in `classes.py`. The gate README describes it together with the risk, and the line is not enabled. The owner decided on 29 September (decision 1 in the [design document](../../05-publication-design.md)) that the exemption covers only the semantic comparison and scanner warnings, and that generated pages get the checks of an experiment (decision 4). The 30-minute condition can be checked only after the new image goes into use, so the task stays in progress.
