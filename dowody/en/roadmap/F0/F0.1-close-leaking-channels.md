# F0.1. Turn off public access to artifacts made before the rules

[← F0](../F0-leaks-and-gate.md)

## Why

Some engine artefacts, the container image and the Python package, were publicly available before the project rules were written down. The image was rebuilt automatically on every change in the repository, so new changes became public straight away. We close this channel first and check the rest afterwards (F0.2).

## What to do

1. Change the visibility of the public container images in the registry to private, together with helper images built from the same repository.
2. In the workflow that builds the images, turn off the publishing step. Building can stay; publishing returns in F1.6.
3. On the server, set up image pulls with a read-only token, so that updates keep working once the images are no longer available anonymously.
4. Delete the old package release from the public registry. Marking the release as withdrawn is not enough, because the files can still be downloaded.
5. Record in the private log what was turned off and when.

## Done when

An unauthenticated request to the registry API returns an authorisation error for every tag of both images, the PyPI page shows neither release 0.1.0 nor files to download, the workflow has no publishing step, and `podman pull` on K12 works after logging in.

## Notes

Whatever has already been downloaded cannot be recalled. This task limits the damage from now on; F0.2 establishes what was visible and where.

## Progress

- 2026-09-27: step 1 done, the images in the registry are private and a request without login returns an authorisation error. Steps 2 to 5 are pending.
- 2026-09-28: step 3 done, the server pulls images after logging in. Step 4 done by the owner: the old package release is deleted. Step 2 was replaced by F1.6: images reach the registry only after the gate scan, and all packages are private. Step 5 is pending.
