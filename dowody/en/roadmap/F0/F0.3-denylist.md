# F0.3. List of forbidden names and its hashed version

[← F0](../F0-leaks-and-gate.md)

## Why

The scanner has to know what to look for, and the public repository must not contain that knowledge. So the list exists in two forms: a private, readable one, and a public one made of HMAC hashes that cannot be reversed or checked against a dictionary without the key.

## What to do

1. Collect names from private sources: the client and sub-project registry of the private Exocortex, names of people from professional context, project code names, names of client systems and products, domains and email addresses, fragments of folder paths from professional work, everything F0.2 turned up.
2. Generate variants for each name: Polish inflected forms, versions without diacritics, joined and separate spelling, abbreviations.
3. Save the list as a private YAML file outside the repository and in the private part of the vault.
4. Write a script (code in English) that normalises each entry (NFKC, lower case, single spaces) and computes HMAC-SHA256 with a secret key for every word n-gram of length 1 to 4.
5. Keep the key only in CI secrets and on the publishing server. The hash file goes into the public repository.

## Done when

Every client in the private registry has at least its name and inflected forms on the list. The script run on two machines with the same key produces an identical hash file. No entry can be recovered from the hash file without the key, which we check by hashing a dictionary of company names without the key and finding no matches.

## Notes

The list is extended with every new client project. Adding an entry means changing the private file and regenerating the hashes, with no code change.
