# F0.6. Comparison with the private corpus

[← F0](../F0-leaks-and-gate.md)

## Why

A list of names will not catch a fragment with the names removed, or a paragraph rewritten in other words. This layer checks whether text meant for publication is similar to anything in client material, whatever names it uses.

## What to do

1. On K12, inside the private network, a small service with a single endpoint: it takes text and returns `similar: true/false`, the highest score and a rule id. It never returns content from the private corpus.
2. Two checks. Literal match: a MinHash index of shingles (8 characters and 6 words) built from the private corpus. Semantic match: paragraph embeddings of the input text compared with paragraph embeddings of the private corpus (the bge-m3 model already runs locally).
3. Calibrate thresholds on two sets, both kept private: paragraphs from the private corpus rewritten by a local model (these must be caught) and public texts on similar topics (these should pass). Set the threshold so that no rewritten paragraph passes, and record how many public texts are stopped at that threshold.
4. The publisher calls the service for every text file.

## Done when

No rewritten paragraph from the calibration set passes. The false alarm rate on public texts is measured and recorded. Public documentation describes the method and the overall results; a private report holds the details.

## Notes

The service has read access to the indexes only, not to the private database. Queries are not logged together with their content.
