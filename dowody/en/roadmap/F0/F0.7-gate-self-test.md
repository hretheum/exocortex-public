# F0.7. Nightly gate test

[← F0](../F0-leaks-and-gate.md)

## Why

A scanner that nobody checks stops working without warning sooner or later: a file format changes, a library changes, someone adds an exception. This test confirms every day that the gate catches what it should.

## What to do

1. Generate canaries: random strings added to the list of forbidden names and to the private corpus. The public test suite uses only canaries, never real names.
2. Build at least 50 cases: a canary in plain text, in different letter case, in an inflected form, without diacritics, with a zero-width character inside, with look-alike characters, split by a line break, in a code comment, in image EXIF, in PDF metadata, in a DOCX comment, in a file inside a wheel, in a container image layer, in a commit author's email. Plus rewritten paragraphs for F0.6.
3. A separate private suite with real names, run only locally.
4. A nightly job runs both suites. If even one case passes, the publisher gets locked (a flag file it checks before every run) and the author gets a notification.
5. Also record the result on a clean control corpus, to follow the false alarm rate over time.

## Done when

The suite has at least 50 cases and all of them are caught. A deliberately broken rule (for example normalisation turned off) gives a red result and a locked publisher the following night. Results of the nightly runs are published in the repository.
