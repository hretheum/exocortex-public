# F0.4. Text and file scanner

[← F0](../F0-leaks-and-gate.md)

## Why

This is the main layer of the gate. Every file goes through this scanner before publication, locally before each commit and in CI before pushing.

## What to do

A Python command line tool, `leakgate`, with code and messages in English. `leakgate scan <paths>` checks:

1. Names from the list: text normalised as in F0.3, word n-grams of length 1 to 4, HMAC with the key, comparison with the hash file. Normalisation also removes zero-width characters and replaces look-alike characters (for example Cyrillic "а" and Latin "a").
2. Personal data: email addresses, phone numbers, Polish PESEL, NIP and REGON numbers with checksum validation, IBAN, first and last names through named entity recognition (the module from the parawan project, built on Presidio). Exceptions, such as the project author, go on an explicit allowlist.
3. File metadata: EXIF and location in images, author, comments and revision history in PDF and DOCX. By default the scanner strips them and reports it, and rejects files of unknown format.
4. Paths: patterns of folders from professional work in file names and in content.
5. Git: author email addresses and messages of the commits about to be pushed.

Non-zero exit code on any match. The JSON report contains the file, the line, the rule id and a hash of the match. It never contains the matched text.

It runs as a `pre-commit` hook in the repository and as a CI step before every push.

## Done when

Unit tests cover every rule with at least one matching case and one clean case. The scanner run over the whole current `dowody/` folder reports no matches. CI logs contain no match content, which we check with a test that searches the log for a planted canary.

## Notes

False positives are handled with an allowlist that has a justification for each entry, never by turning a rule off.
