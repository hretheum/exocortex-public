# F0.5. Package and container image scanner

[← F0](../F0-leaks-and-gate.md)

## Why

A Python package or a container image can contain files that are not in the code under review, because the build copies the whole folder or adds generated files. Checking the repository alone will not catch that. We have to check what actually goes to the registry.

## What to do

1. `leakgate scan-wheel` and `leakgate scan-sdist`: unpack the archive into a temporary folder and run the F0.4 scanner on it.
2. `leakgate scan-image`: export the image (`skopeo copy` to a directory or `podman save`), unpack each layer separately and run the scanner on each. Separately check the image configuration: environment variables, labels and build command history.
3. Set the workflow order to build, scan, and only then push. Pushing requires a green scan of the same artifact, identified by its digest.

## Done when

An image deliberately built with a canary in a documentation file is stopped, and the same image without the canary passes. The same for a wheel and an sdist. The workflow has no path that pushes an artifact without scanning it.

## Notes

In F1.6 `.dockerignore` switches to an allowlist (exclude everything, admit what is needed). The scanner stays anyway: the allowlist protects against a configuration mistake, the scanner against a content mistake.
