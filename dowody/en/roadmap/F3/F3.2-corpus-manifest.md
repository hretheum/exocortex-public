# F3.2. Downloading the corpus and the manifest

[← F3](../F3-first-pass.md)

## Why

Downloading has to be repeatable, and every document needs a fixed id and a checksum, so that samples and results always refer to the same texts.

## What to do

1. A download script (code in English): abstracts from the arXiv API for the ids from F3.1, recording the paper version and the download date.
2. Export of the engine's summaries from the database for the same ids, with the model version and the summary date. Deduplication by arXiv id.
3. A manifest, `manifest.csv`: arXiv id with version, source address, download date, SHA-256 of the normalised abstract and summary, character count, basis for use.
4. Texts that may be shared go into the repository together with the manifest. For the others the repository holds only the manifest and the script.
5. Load the corpus into the lab through the Capture API.

## Done when

The manifest is in the repository. The script run a second time on another machine gives the same checksums, or a difference report with explanations (for example a document changed at the source). The corpus is in the lab graph.
