# F3.7. Pilot: configuration matrix

[← F3](../F3-first-pass.md)

> The task depends on F3.6 (quick test and gate G1), which is "to do"; the first extraction run on the tuning sample has been in progress since 30 September. It cannot be started before the G1 decision, and it will start only on a `GO` decision. No pilot run has taken place yet.

## In brief

The pilot is a larger version of the quick test. We repeat the same measurement on 4 to 8 configurations, that is, combinations of settings (model, answer schema with or without the mode field, whole documents or fragments), and on different documents than in the first test. This tells us whether the result depends on the chosen model and how much work it costs.

## Why

The quick test used one model and one way of splitting text, so its result could be an accident of that choice: another model might behave differently. The pilot checks whether the effect holds for other models and settings, and what it costs in time and in tokens, the units in which a model's work is counted. Without it we would have one result of unknown reliability.

## What to do

1. A matrix of 4 to 8 configurations: two local models from different families, the schema with and without the mode field, whole documents and fragments.
2. Run the matrix on the pilot sample (documents outside tuning and the control set), in the night window, with the queue grouping jobs by model.
3. Collect telemetry: share of fragments without a valid answer, number of claims, tokens, time, GPU use (the server's graphics card).
4. Publish the table of mechanical results (without human ratings, which come in F3.8).

## Done when

All configurations have finished runs, the telemetry table is in the repository, and runs that ended in an error are described in the log with their cause.
