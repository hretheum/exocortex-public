# F2.3. Header schemas and final templates

[← F2](../F2-lab.md)

> **Status: done** · as of September 30, 2026
>
> Headers of four kinds of files (hypothesis card, run note, gate decision, roadmap task file) have schemas, that is, written rules about which fields must be present and which values are allowed in them. The `docschema` script checks files against these rules in CI (the automatic tests) and in the publisher, and an error names the file, the field and the reason. The templates are in `dowody/pl/templates` and `dowody/en/templates`, and a check of the whole `dowody` folder on September 30 covered 52 files with a schema and reported no errors. The three cases from the done condition (missing field, wrong value, unknown field) have tests, and they pass.

## In short

This task sets how the headers of lab files must look (the block of fields at the start of a file) and enforces it automatically. A file with an error in its header is rejected with a readable message.

## Why

The lab reads files written by people: hypothesis cards, notes, decisions. If someone makes a typo in the name of the field that holds the success threshold in a hypothesis card, the program must neither skip it nor read it in its own way, because the threshold would stop applying without anyone noticing. A fixed set of fields and an automatic check make such a mistake show up at once, with the field name and the reason.

## What to do

1. JSON Schema definitions (descriptions of the allowed fields and values) for headers: hypothesis card, experiment note, gate decision, roadmap task file.
2. A validator (a program that checks files; code in English) run in CI, in the publisher and in the processors.
3. Final templates in `dowody/pl/templates/` and `dowody/en/templates/`, matching the schemas. The working templates in that folder are the starting point.
4. Experiment folder layout: `dowody/pl/experiments/<slug>/` and `dowody/en/experiments/<slug>/`, each with `hypothesis.md`, `run-*.md` notes and `gate-*.md` decisions.

## Done when

The templates pass validation, and three prepared bad files (missing field, wrong value, unknown field) are rejected with a readable message.
