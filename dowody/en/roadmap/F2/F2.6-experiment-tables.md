# F2.6. Experiment tables and the control set lock

[← F2](../F2-lab.md)

## Why

Exocortex already has a bench for comparing configurations: tables with a job queue, leases, results and cost telemetry. It is tied to one kind of experiment, though (claim extraction). We need a general version.

## What to do

1. A migration in the lab database with the tables `experiments`, `exp_configs`, `exp_samples`, `exp_jobs`, `exp_results`, `exp_judgments`. Keep from the existing bench the leased queue with retries, and the recording of model, provider (local or remote), tokens, cost and latency. Store results as JSON so that a new kind of experiment needs no schema change.
2. `exp_samples` with the sampling seed, a checksum of the content and the data class. In the lab the only allowed class is `public`.
3. Control set lock: a `touched_at` field. A second read of the control set for the same hypothesis version raises an exception.
4. The queue picks jobs grouped by model, so that llama-swap does not switch models on every job.
5. A toy experiment (for example counting document lengths) to test the whole path.

## Done when

The toy experiment goes through the queue and records its results. A second read of the control set ends with an exception. A queue test shows that jobs for two models run in two blocks, not alternately.
