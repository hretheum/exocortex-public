# F2.2. Allowlist of sources

[← F2](../F2-lab.md)

## Why

Everything that enters the lab goes through a single entry point (the Capture API). If that entry point accepts only sources from an explicit list, nothing can be brought in sideways, not even by mistake.

## What to do

1. A file `lab/sources.yaml` in the repository: for each source, its type, address or address pattern, licence or basis for use, and the person who added it.
2. The lab Capture API rejects any `source_type` not on the list. Adapters that fetch from the web check the address domain against the list before fetching.
3. The `dowody/` folder is allowed from the start. External sources are added in F3 and F5.
4. Test: an attempt to send content with a disallowed type, and an attempt to fetch from a disallowed domain, both end in a refusal and a log entry.

## Done when

The list is public in the repository, both test cases end in a refusal, and adding a source requires a commit with a reason.

## Progress

- 2026-09-28: the list `lab/sources.yaml` is in the repository and goes into the engine image. For now it has one source, the `dowody` folder. Every entry needs a basis for use, an author and a reason, so adding a source is a commit with a justification. The lab Capture API refuses with code 403 any type and address not on the list, and adapters check the domain before downloading. Every refusal goes to the log as one entry without content. Checked on the server: an email and a note from outside `dowody` were refused, a document from `dowody` went through. The F2.1 isolation check fails if the lab runs without the list.
