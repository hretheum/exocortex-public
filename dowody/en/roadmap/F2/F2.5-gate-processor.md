# F2.5. Handling gate decisions

[← F2](../F2-lab.md)

## Why

A gate decision is the easiest place to change a criterion quietly. The processor has to make sure that a decision refers only to the thresholds in the frozen card.

## What to do

1. A `gate_decision` processor reads `gate-*.md` files, validates the header and links the decision to a specific hypothesis version.
2. It compares the thresholds quoted in the decision with those in the frozen card. A difference is allowed only for a `PIVOT` decision, which requires a new version of the card.
3. A decision without `human_validated: true` does not change the state of the hypothesis and is not visible to the reference card compiler.
4. Every decision has to point to the ids of results in the experiment tables (F2.6) that it rests on.
5. The hypothesis state in the graph changes according to the decision: `GO`, `NO-GO`, `PIVOT`, `NOT-NOW` (with a condition for coming back), `CLOSED`.

## Done when

Three test cases behave as expected: a correct decision changes the hypothesis state, a decision with a different threshold and no `PIVOT` is rejected, an unapproved decision changes nothing.
