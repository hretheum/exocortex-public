# F2.5. Handling gate decisions

[← F2](../F2-lab.md)

> **Status: done** · as of September 30, 2026
>
> The gate decision processor runs in the lab (`exocortex/lab/gates.py`). It accepts a decision only when both language versions are approved, the card is frozen and not tampered with, the thresholds match the card (exception: PIVOT with a new version of the card), the result ids it names exist in the experiment tables, and a NOT-NOW decision has a return condition. Three cases from the done condition and four more are tests that pass on the real database image. The dependency F2.4 is in progress, and according to its notes only the path on the test card's files is missing; the progress log does not yet contain a real gate decision.

## In short

After a quick test a person decides what happens next with the hypothesis. This task checks automatically that such a decision rests on the results and on thresholds written down in advance.

## Why

A gate is a checkpoint where a person compares the result with the threshold in the hypothesis card and chooses what happens next. After the measurement it is easy to change the criterion: the result is too low, so we decide the threshold was too ambitious. The processor rejects a decision that refers to a different threshold than the frozen card, unless the hypothesis gets a new version, which is visible in the history. Without this, the preregistration from F2.4 would protect nothing, because a decision could be based on a different threshold.

## What to do

1. A `gate_decision` processor (the program that handles gate decisions) reads `gate-*.md` files, validates the header and links the decision to a specific hypothesis version.
2. It compares the thresholds quoted in the decision with those in the frozen card. A difference is allowed only for a `PIVOT` decision (a change of the hypothesis), which requires a new version of the card.
3. A decision without `human_validated: true` does not change the state of the hypothesis and is not visible to the reference card compiler (the program that builds the reference project card from the results).
4. Every decision has to point to the ids of results in the experiment tables (F2.6) that it rests on.
5. The hypothesis state in the graph changes according to the decision: `GO` (we go on), `NO-GO` (we stop), `PIVOT` (we change the hypothesis), `NOT-NOW` (we postpone, with a condition for coming back), `CLOSED` (we close it, because the question is settled).

## Done when

Three test cases behave as expected: a correct decision changes the hypothesis state, a decision with a different threshold and no `PIVOT` is rejected, an unapproved decision changes nothing.

## Progress
