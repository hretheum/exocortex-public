# F2.9. Lab jobs on demand

[← F2](../F2-lab.md)

## Why

The commands that run samples, work through the queue and handle blind rating exist in the code, but the server has no units of its own for them. The first experiment and every later one needs them every time, so starting one has to be a single repeatable command under the same isolation as the rest of the lab.

## What to do

1. Quadlet units for the commands `run` (one sample of one experiment, one instance per experiment), `work` (work through the queue grouped by model, with a timer for the night that can be switched on) and `blind` (drawing and importing ratings). The same network, secrets and volumes as the radar unit.
2. Next to them the unit for drafts of the business applications section (F8.1), which is already in the image but not installed, and every later lab unit, such as the graph package (F8.2).
3. A rule in the deployment README: every recurring lab job has an on-demand run with a single command. A test in the repository checks that every unit with a timer has an on-demand counterpart.
4. Installation on the server from the engine image, without source code, and a trial run on the toy experiment.

## Done when

The toy experiment goes through `run`, `work` and `blind` started as units on the server, and the nightly isolation test still passes.

## Progress

- 2026-09-30: the `run`, `work` (nightly timer switched off) and `blind` units and the unit for drafts of the applications section are installed on the server from the engine image. The toy experiment went through all three, the nightly isolation test passes, and a test in the repository checks that every timer has an on-demand counterpart.
