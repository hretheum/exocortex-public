## In brief

This task makes it possible to start every lab step with a single command on the server: a trial run of an experiment, working through the job queue and rating results blind (without knowing which setting produced a given result). The steps run under the same safeguards as the rest of the lab, that is, without access to private data.

## Why

Until now the lab's steps existed only as code, and the server had no ready-made services for them. Every experiment needs them every time, so starting one has to be a single command. Assembling the command by hand invites small differences, for example different network or password access, and then a result is hard to repeat and there is no certainty that the step runs under the same safeguards. A ready-made service always starts the same way. Example: to draw the items for blind rating, one command is enough instead of putting together several manual steps.

## What to do

1. Quadlet units (descriptions of services that the system on the server starts and watches) for the commands `run` (one sample of one experiment, a separate instance for each experiment), `work` (work through the job queue in groups by model, with a timer for the night that can be switched on) and `blind` (drawing the items to rate and importing ratings). The same network, secrets (passwords and keys) and volumes (data stores) as the radar unit, the weekly review of new papers.
2. Next to them the unit for drafts of the business applications section (F8.1), which is already in the engine image but not installed, and every later lab unit, such as the build of the graph package (F8.2), a data package for publication.
3. A rule in the deployment README: every recurring lab job has an on-demand run with a single command. A test in the repository checks that every unit with a timer has an on-demand counterpart.
4. Installation on the server from the engine image, without source code, and a trial run on the toy experiment.

## Done when

The toy experiment goes through `run`, `work` and `blind` started as units on the server, and the nightly isolation test (a check that the lab has no connection to the private database) still passes.
