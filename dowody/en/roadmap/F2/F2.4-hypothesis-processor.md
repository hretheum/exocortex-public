## In short

Before an experiment is computed, its hypothesis and success thresholds are written down and frozen together with a checksum, a short fingerprint of the content. This task does that recording automatically and notices when someone changes a frozen card.

## Why

It is easy, even unconsciously, to fit the success threshold to a result we already know: the result was 55%, so we decide the threshold was 50%. Preregistration means writing down in advance what we measure and what result counts as success. The card with the threshold goes to the public repository before the measurement, and the date it was saved in the repository history shows when it was created. An outside reader can compute the card's checksum and compare it with the record, so there is no need to take our word for it. Without this task, every claim that the thresholds were set beforehand would rest on our word alone.

## What to do

1. A `hypothesis_card` processor (the program that handles hypothesis cards) reads both language versions of the card, validates the header and writes the hypothesis as a node, that is, a point in the lab graph (a network of links between pieces of information).
2. When a card gets `human_validated: true`, the processor computes a SHA-256 checksum (a short fingerprint of the content that changes with every change of the text) over the normalised content of both versions (excluding state fields that change along the way) and writes an entry to `dowody/prereg.jsonl`: id, version, checksum, date. The publisher sends this entry with the card, so the commit (a saved change in the repository history) in the public repository serves as the timestamp.
3. Any later change to the content of a frozen card without raising its version number marks the card as tampered. The experiment page shows this in red, and gates for that hypothesis are blocked.
4. A new version of a card points to the previous one in the `supersedes` field. Both stay in the repository.
5. A verification script in the repository: anyone can compute the checksums of the cards and compare them with `prereg.jsonl` and with the commit date.

## Done when

Approving a test card creates an entry in `prereg.jsonl` that is visible in the repository. Changing a threshold in that card without a new version marks it as tampered. The verification script run on a fresh clone of the repository confirms the checksums.
