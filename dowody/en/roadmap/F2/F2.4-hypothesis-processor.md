# F2.4. Handling hypothesis cards and preregistration

[← F2](../F2-lab.md)

## Why

Preregistration is the main safeguard against fitting the method to the result. It has to be automatic and checkable by an outsider, without taking our word for it.

## What to do

1. A `hypothesis_card` processor reads both language versions of the card, validates the header and writes a hypothesis node into the lab graph.
2. When a card gets `human_validated: true`, the processor computes SHA-256 over the normalised content of both versions (excluding state fields that change along the way) and writes an entry to `dowody/prereg.jsonl`: id, version, checksum, date. The publisher sends this entry with the card, so the commit in the public repository serves as the timestamp.
3. Any later change to the content of a frozen card without raising its version number marks the card as tampered. The experiment page shows this in red, and gates for that hypothesis are blocked.
4. A new version of a card points to the previous one in the `supersedes` field. Both stay in the repository.
5. A verification script in the repository: anyone can compute the checksums of the cards and compare them with `prereg.jsonl` and with the commit date.

## Done when

Approving a test card creates an entry in `prereg.jsonl` that is visible in the repository. Changing a threshold in that card without a new version marks it as tampered. The verification script run on a fresh clone of the repository confirms the checksums.
