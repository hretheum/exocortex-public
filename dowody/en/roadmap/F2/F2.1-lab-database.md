# F2.1. Separate database and processes for the lab

[← F2](../F2-lab.md)

## Why

The separation has to hold even when someone makes a mistake. The lab runs on the same server as the private instance, so we need a checkable way to rule out any of its processes reaching private data.

## What to do

1. A separate database container (Quadlet `exocortex-lab-db`) with its own volume, its own loopback port and its own role.
2. Separate units for the lab processes (API, scorer, compiler, publisher) with their own environment file that holds no credentials for the private instance.
3. From the vault, the lab sees only the synchronised `dowody/` folder.
4. Schema migrations run on the lab database from the public repository.
5. A test script: from the lab container, try to connect to the private database (every known address and port) and try to read the private vault folder. Both must fail.

## Done when

The lab database runs with the current schema, and the test script ends with two refusals. The script is in the repository and runs every night together with the F0.7 gate tests.
