# F1.2. Przemianować obecne repozytorium i założyć nowe

[← F1](../F1-public-repo.md)

## Po co

Wariant A z F1.1 wymaga zwolnienia adresu `hretheum/exocortex` i założenia pod nim nowego, pustego repozytorium z włączonymi zabezpieczeniami, zanim trafi tam pierwszy plik.

## Co zrobić

1. Przemianować obecne repozytorium na `exocortex-private`. GitHub przekierowuje stary adres na nowy, dopóki pod starym nie powstanie inne repozytorium, więc krok 2 trzeba wykonać zaraz potem.
2. Założyć publiczne repozytorium `hretheum/exocortex` z jednym plikiem README.
3. Ochrona gałęzi `main`: tylko przez pull request albo przez konto publikatora, wymagane zielone kontrole: skaner (F0.4), test parzystości (F1.7), sprawdzanie języka (F1.8).
4. Dodać sekret z kluczem HMAC do list nazw (F0.3).
5. Zaktualizować zdalne adresy w lokalnych klonach na Macu i na K12 oraz odwołania do repozytorium w workflow i w jednostkach systemd.

## Gotowe, gdy

Stare repozytorium jest prywatne pod nową nazwą, a lokalne klony i K12 z nim działają. Nowe repozytorium jest publiczne, README przechodzi wszystkie kontrole, a próba wysłania commita z kanarkiem bezpośrednio do `main` zostaje odrzucona.
